# Data Contract — Engineering Notes (internal)

**Companion to `data-contract.md` v1.0. Not published. This is the list of things the code must do for the public promises to be true.**

Implementation specifics live here on purpose: provider names, key handling, caps, and the redaction pattern list. Keep the public document plain-language and keep this one exact.

## Current stack (Aug 26, 2026)

- Backend + Postgres: DigitalOcean App Platform (Basic web service) + Managed PostgreSQL (Basic 1 GiB, single node, SFO). DB reachable only from the app via Trusted Sources. Daily backups + PITR are native to Managed PostgreSQL.
- Static site, docs, browser tools: Cloudflare Pages on blackstonescripts.com. Zero tenant data.
- Off-platform backup copies: Cloudflare R2 (free tier), encrypted before upload with a key held outside DO.
- Identity: Clerk (Discord OAuth, org/team model). Billing: Stripe. Alerts: Discord webhooks configured per tenant.
- Key management: per-tenant data keys wrapped by a master key held only in App Platform encrypted environment variables. Rotation procedure to be written before first paying tenant.

## Appendix A — Engineering changes this contract requires (pre-release, so no version bump)

The wire protocol as written on August 7 does not yet honor Class I. Before the first real agent ships:

1. **`player.join`, `player.drop`, `econ.txn`, `vehicle.spawn`, `staff.action`:** replace `license` (raw `license:abc123`) with `player_id` — an HMAC-SHA256 pseudonym, hex, truncated to 32 characters, keyed by the tenant key. `identifiers_hash` on `player.join` is redefined as the pseudonym of the *sorted, concatenated* identifier set (so alt-account detection still works within a tenant without any raw identifier). Keep `player` (display name) as Class N.
2. **`staff.action`:** `staffer` and `target` become `{ name, player_id }` objects. Free-text `detail` passes the Class S filter at the agent before send and again at ingest.
3. **`player.drop.reason`:** same Class S filter. txAdmin reasons occasionally embed identifiers; strip `discord:`/`license:` tokens to their pseudonyms.
4. **`agent.boot`:** add `contract_version`, `scopes[]`, `redaction: { secrets: true, identifiers: "hmac" }`, and `key_fingerprint` (first 8 hex of SHA-256 of the tenant key). Agent refuses to send if `redaction.secrets` is false.
5. **New command `resolve_pseudonym`:** portal → agent, returns display name and identifiers to the requesting staff session only; the ingest server logs that a resolution happened (who, when, tenant), not the result.
6. **Ingest:** never log request bodies; the existing `record` path must store `data` only after the Class S filter; rejections must not echo the offending value in `detail` (say "value matched secret pattern," never the value).
7. **Tenant key:** generated by the agent at first link (`agent/key.lua` writes it to the resource's own data directory, never to `server.cfg`), 32 random bytes, never transmitted. Rotation is an owner action that breaks continuity of pseudonyms on purpose.
8. **Free tools redaction module:** a single shared browser module (`redact.js`) used by every tool, with the pattern list versioned and published, and a test corpus of real (donated, already-redacted) logs so no pattern regresses.

## Appendix B — Class S pattern families the redaction module must cover

`sv_licenseKey`, `steam_webApiKey`, `rcon_password`, `mysql_connection_string` and any `mysql://`, `postgres://`, `mongodb://` URI, Discord webhook URLs (`discord.com/api/webhooks/…`, `discordapp.com/…`), Discord bot tokens (three dot-separated base64 groups), `Bearer …`, `Authorization:` headers, Cfx keymaster key formats, `txAdmin` session tokens, Tebex secret keys, generic `api_key=`/`apikey=`/`token=`/`secret=`/`password=` assignments in Lua, cfg, JSON, and env syntax, and IPv4/IPv6 literals paired with a port.

Each family has a unit test with a positive and a near-miss case. A redaction that can't be tested doesn't ship.
