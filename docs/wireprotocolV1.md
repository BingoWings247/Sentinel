# Sentinel Wire Protocol — v1

The contract between the on-server agent and the Sentinel backend.
Everything else in the system hangs off this document. Changes require a version bump.
(v1 amended pre-release, Aug 7 2026: added `vehicle.spawn`, provenance rule.)
(v1 amended pre-release, Oct 7 2026: added `GET /v1/whoami`; `player_id` pseudonyms replace raw `license`; `econ.txn.account`; `econ.set`.)

---

## Transport

- `POST https://api.<sentinel-domain>/v1/ingest`
- `Content-Type: application/json`
- `Authorization: Bearer <server_token>` — issued at link time, **never in the body**
- Agent flushes a batch every **5 seconds** or at **100 buffered events**, whichever comes first
- Hard caps: **500 events / 256 KB** per batch. Agent splits oversized batches.

### Identity lookup

- `GET https://api.<sentinel-domain>/v1/whoami` with the same bearer token
- Returns `{ "ok": true, "protocol": 1, "server_id": "srv_...", "name": "..." }`, or `401 auth_failed`
- The agent calls it at boot, so the only setting an owner has to paste is the token.

## Batch envelope

```json
{
  "v": 1,
  "server_id": "srv_01J3XKQ8ZM4T",
  "seq": 4471,
  "sent_at": 1753300000123,
  "agent": {
    "version": "0.1.0",
    "artifact": "7290",
    "resource_count": 142,
    "uptime_s": 224640
  },
  "events": []
}
```

| Field | Type | Rules |
|---|---|---|
| `v` | int | Protocol version. Always first. Backend rejects unknown versions with `unsupported_version`. |
| `server_id` | string | Issued at link time. Must match the token's server or the batch is rejected. |
| `seq` | int | Monotonic per agent boot. Lets the backend detect gaps (dropped batches) and replays. Resets to 0 on agent restart — pair with `agent.boot` event. |
| `sent_at` | int | ms epoch, agent clock. Backend also stamps `received_at`; both are stored. Never trust agent clocks for ordering across servers. |
| `agent` | object | Health snapshot. Powers the artifact-version flag and "last batch Ns ago" in the portal. |
| `events` | array | 0..500 events. An empty array is a valid heartbeat. |

## Event object

```json
{
  "id": "evt_01J3XKQ9F2A7",
  "t": 1753299998456,
  "type": "player.drop",
  "src": "server",
  "data": {
    "player": "Kaiden_R",
    "player_id": "9f2c41d07ab35e1c8d6f0a4b2e7c9d13",
    "reason": "Banned: mod menu detection (txAdmin)",
    "session_s": 5460
  }
}
```

| Field | Type | Rules |
|---|---|---|
| `id` | string | ULID generated by the agent. **Idempotency key** — backend dedupes on it, so retries with the same ids are always safe. |
| `t` | int | ms epoch when the event occurred (not when it was sent). |
| `type` | string | Namespaced dot notation, lowercase. Unknown types are **accepted and stored raw**, flagged `unrecognized` — never dropped (forward compatibility). |
| `src` | string | `"server"` or the emitting resource name. |
| `data` | object | Type-specific payload. Validated per-type at ingest. |

## Event type registry (v1)

| Type | Fired when | Key data fields |
|---|---|---|
| `agent.boot` | Agent starts | `config_used`, `fallbacks_applied[]` (ARCH Rule 1: self-report) |
| `agent.error` | Agent-internal fault | `code`, `detail` (ARCH Rule 5: never silent) |
| `server.hitch` | Hitch warning observed | `ms`, `players`, `active_resources` |
| `server.resource` | Resource start/stop/restart | `resource`, `action`, `by` (if known) |
| `server.manifest` | Resource added/removed on disk | `resource`, `change` |
| `player.join` | Player connects | `player`, `player_id`, `identifiers_hash` (HMAC pseudonyms, never raw identifiers) |
| `player.drop` | Any drop, any cause | `player`, `player_id`, `reason`, `session_s` — the ban/kick ledger lives here |
| `perf.resmon` | 30s aggregation window closes | `resource`, `avg_ms`, `peak_ms`, `samples` |
| `econ.txn` | Money moves | `player`, `player_id`, `direction`, `amount`, `account`, `source`, `via`, `balance_after` |
| `econ.set` | Balance overwritten | `player`, `player_id`, `account`, `value`, `delta` (if known), `source`, `via` |
| `vehicle.spawn` | Vehicle created for a player | `model`, `method` (garage/dealer/admin/script), `source`, `by` |
| `staff.action` | Staff-privileged act observed | `staffer`, `action`, `target`, `detail` |
| `net.rate` | 60s window closes | `event`, `top_sender`, `count` — event-spam visibility |

**Sampling discipline:** `perf.resmon` and `net.rate` are *aggregated windows*, never per-tick raw
streams. This is what keeps a 64-slot server inside modest bandwidth.

## Provenance rule (adapters contract)

All `econ.*` and `vehicle.*` events MUST populate `data.source` with the
concrete cause (e.g. `"job:police:paycheck"`, `"qb-vehicleshop:purchase"`,
`"admin:spawn:<staffer>"`). If the source cannot be determined, emit
`source: "unknown"` — never omit the field. Unsourced is itself signal:
detection treats outcomes without causes as having no innocent explanation.
This rule is what makes scalpel-grade detection possible; adapters that
cannot honor it for a given event class must say so in their README.

*Amended Oct 8 2026 (agent 0.1.1):* on frameworks that announce money changes
themselves (Qbox/QBCore `OnMoneyChange`), the invoking resource is always the
framework. Adapters therefore set the event `src` to the resource named by a
`<resource>:<action>` reason when that resource is running, and to the
framework otherwise; `data.via` names the framework. A reason that says
nothing (`unknown`, `Unknown`, blank) is sent as `"unknown"`, lowercase. The
backend applies the same folding to events from older agents.

## Response

```json
{
  "ok": true,
  "received": 37,
  "deduped": 0,
  "commands": [
    { "cmd": "set_flush_interval", "value": 10 }
  ]
}
```

- `commands` is how the portal talks back to the agent — piggybacked, no inbound connection ever.
- Initial command set: `set_flush_interval`, `set_sample_window`, `request_snapshot`, `reauth`.
- Agent treats unknown commands as no-ops and reports them via `agent.error` (`unknown_command`).

## Rejection (ARCH Rules 4 + 5 at the door)

Every rejection is specific and machine-readable. No batch dies silently.

```json
{
  "ok": false,
  "error": {
    "code": "invalid_event",
    "index": 12,
    "field": "data.amount",
    "detail": "expected number, got string"
  }
}
```

| Code | Meaning | Agent behavior |
|---|---|---|
| `auth_failed` | Bad/revoked token (subscription lapse lands here) | Stop sending, log loudly, retry hourly |
| `unsupported_version` | Protocol `v` unknown | Stop, log "update agent" |
| `invalid_envelope` / `invalid_event` | Shape/range validation failed | Drop the named event only, resend rest, log it |
| `rate_limited` | Backpressure | Honor `retry_after_s`, keep buffering |

## Failure behavior (agent side)

- Ring buffer, **2,000 events max**. On overflow: drop oldest, emit one `agent.error`
  (`buffer_overflow`, with count dropped) — the drop itself is observable.
- Network failure: exponential backoff 5s → 60s cap. Events keep buffering.
- Retries resend the **same event ids** — dedupe makes this free.
